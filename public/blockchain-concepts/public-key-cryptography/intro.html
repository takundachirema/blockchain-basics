Introduction to Public Key Cryptography

Cryptography Basics

Definitions used in this page:
  • Cryptography: The practice of protecting information by transforming it so only authorized parties can read it.
  • Cipher: The algorithm/rule used to transform plaintext into ciphertext and back again.
  • Plaintext: The original readable message.
  • Ciphertext: The scrambled output produced by encryption.
  • Symmetric cryptography: Encryption and decryption use the same shared key.
  • Asymmetric cryptography: Encryption and signatures use a public/private key pair.
  • Digital signature: A cryptographic proof attached to data that shows who signed it and that the data has not been altered.
  • Digital signing: The process of using a private key to create a digital signature for a message or transaction.

Cryptography helps us keep data confidential and verifiable. The basic idea is simple: we start with plaintext, apply a cipher, and produce ciphertext. To recover the original message, we decrypt the ciphertext with the appropriate key.

Symmetric Cryptography

In symmetric cryptography, both sides use the same secret key. The sender encrypts with that key, and the receiver decrypts with that same key.

Symmetric model: The same key is used on both the sender and receiver sides.

Caesar Cipher Example

A classic example of a symmetric cipher is the Caesar cipher, where each letter is shifted by a fixed amount. If we use a shift of +3:

  • Plaintext: HELLO
  • Cipher rule: Shift each letter +3
  • Ciphertext: KHOOR (H->K, E->H, L->O, L->O, O->R)

To decrypt, apply the inverse shift (-3) to recover the original plaintext.

Note: Caesar is useful for learning, but it is not secure for real systems. Modern cryptography uses much stronger ciphers.

Asymmetric (Public Key) Cryptography

Public key cryptography uses two mathematically related keys:

  • Public key: Shareable; used to encrypt data or verify signatures.
  • Private key: Secret; used to decrypt (where applicable) or create signatures.

Asymmetric model: Different keys are used on each side (public key vs private key).

Why This Matters for Blockchain

Blockchains rely heavily on asymmetric cryptography for ownership and authorization. Users keep private keys secret and use them to sign transactions. Networks verify signatures with the corresponding public keys.

Elliptic Curve Cryptography (ECC)

Ethereum uses secp256k1, an elliptic curve also used by Bitcoin. ECC provides strong security with relatively small keys and efficient computation.

How the public key is generated from the private key

In ECDSA-style systems on a curve like secp256k1, key generation works as follows (see Key Generation — ECDSA on Learn Me A Bitcoin):

  • Private key (d): A large, cryptographically random integer chosen from a safe range on the curve (below the curve order n). It must stay secret.
  • Generator point (G): A fixed, standard “starting” point on the curve that everyone agrees on for that curve.
  • Public key (Q): The curve point obtained by scalar multiplication: Q = d × G — you effectively “walk” along the curve from G according to the private key d. The public key is that resulting point (often stored as x and y coordinates, or in compressed form).

Elliptic curve multiplication is a trapdoor or one-way operation in practice: given d, computing Q is fast, but given Q alone, recovering d by trying values is infeasible for a well-chosen private key. That asymmetry is what makes sharing the public key safe while keeping the private key private.

The math works because secp256k1 points form an algebraic group: point addition is well-defined, has an identity point, every point has an inverse, and repeated addition (scalar multiplication) stays inside the same set of valid curve points. So when we compute Q = d × G, the result is guaranteed to also be a point on the same curve.

A public key is fundamentally a point (x, y). It can be encoded in different ways:

  • Uncompressed: both x and y are included.
  • Compressed: full x plus one bit of information (encoded as a prefix) to indicate which valid y is intended.
  • x-only (some schemes): only x is stored under specific protocol rules.

In Ethereum-style account derivation, the address is derived from the uncompressed public key coordinates (x || y) after hashing.

Public key from private key: The private key scales the generator point on the curve to produce the public key point.

Signing and verifying messages uses this same curve math; for the full ECDSA sign/verify walkthrough, see Elliptic Curve Digital Signature Algorithm (ECDSA).

Important: Never share your private key. Anyone with your private key can sign transactions as you.
