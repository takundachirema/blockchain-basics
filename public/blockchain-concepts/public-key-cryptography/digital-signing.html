Digital Signatures and Digital Signing

Core Definitions

Definitions used in this page:
  • Digital signature: A cryptographic proof attached to data that confirms who signed it and that the data was not changed after signing.
  • Digital signing: The process of using a private key to generate a digital signature for a message or transaction.
  • Hashing: The act of transforming data into a fixed-length digest that acts like a compact fingerprint.
  • Hash function: A one-way algorithm that takes input data of any length and outputs a deterministic, fixed-size hash digest.

How Digital Signing Works

A signer starts with a message or transaction, hashes it, and then uses their private key to create a signature from that digest. Anyone can verify the result using the signer's public key.

Digital signing flow: Hash first, sign the digest with the private key, then verify with the public key.

Signing vs Verification (ECDSA in a nutshell)

With ECDSA-style signatures, you don’t sign the full message directly — you sign its hash. Signing uses the private key plus a fresh random value (often called a nonce) to produce a signature (typically two numbers, r and s). Verification uses the public key, the same message hash, and the signature to check if the signature could only have been produced by the corresponding private key. See ECDSA signing for a visual walkthrough.

Sign: private key + message hash → signature. Verify: public key + message hash + signature → valid/invalid.

How ECDSA Computes r and s

In ECDSA, the signature is a pair (r, s). You sign the message hash (not the full message) using private key d, random nonce k, generator point G, and curve order n.

  1. Compute r: first compute R = k x G, then set r = Rx mod n.
  2. Compute s: using message hash z, calculate s = k-1(z + r*d) mod n.
  3. Signature output: the final signature is the pair (r, s).

Security note: k must be fresh and unpredictable for each signature. Reusing or leaking k can expose the private key.

How r and s Are Used in Verification

During verification, the network takes the signature pair (r, s), the message hash, and the signer’s public key. It then uses the public key together with s to reconstruct a check value from the signed data.

Finally, it compares that reconstructed value against the signature’s r. If they match, the signature is valid; if they do not match, verification fails.

What Hashing Is

Hashing converts input data (for example plain text or a transaction payload) into a fixed-length digest. In digital signing, we sign this digest instead of signing the full raw message directly.

Hashing flow: Input data goes through a hash function and produces a fixed-length digest.

Properties of a Good Hash Function

  • Deterministic: The same input always gives the same output.
  • Fast to compute: Efficient enough for frequent signing and verification.
  • Preimage resistant: It is infeasible to recover the original input from only the hash.
  • Second-preimage resistant: It is infeasible to find a different input with the same hash as a given input.
  • Collision resistant: It is infeasible to find any two different inputs that produce the same hash.
  • Avalanche effect: Small input changes produce very different hash outputs.

Why Hashing Is Necessary for Digital Signing

Hashing is a required step in practical signature systems for both security and efficiency:

  • Efficiency: Signing a short fixed-size digest is much faster than signing large raw data directly.
  • Deterministic verification: Verifiers hash the received message the same way and compare against what the signature proves.
  • Tamper detection: Even a tiny message change produces a very different digest, so altered data fails signature verification.
  • Standardized input: Hash functions convert variable-length messages into a fixed-size value expected by digital signature algorithms.
Important: Digital signatures provide authenticity and integrity, but they do not encrypt the message contents by themselves.
