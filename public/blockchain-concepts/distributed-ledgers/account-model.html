Account Model

What Is the Account Model?

In the account model, ledger state is stored as account records, where each account has a balance and a nonce. Transactions directly decrease the sender's balance and increase the receiver's balance.

Definitions used in this page:
  • Account: A state entry identified by a public key/address.
  • Balance: Spendable value currently owned by the account.
  • Nonce: A per-account counter that must strictly increase with each transaction.
  • Unsigned transaction: Transaction data before the signature field is filled.

Transaction Shape

A typical account-model transaction includes: from, to, value, fee, nonce, and a signature sigma. The signature is made over the unsigned transaction fields.

Transaction fields: Account-model transactions include sender-controlled parameters, destination, value, and a digital signature.

State and Nonces

The state stores both balances and nonces per account. The nonce is critical because two transfers can look identical in every other field. The nonce makes each transaction unique and ordered per sender.

Account state fields: Nonce tracks transaction ordering, while balance and other fields define current account state.

How Double Spending Is Addressed

In the account model, double spending is prevented primarily by the nonce rule plus standard validity checks:

  • Exact nonce requirement: A transaction is valid only if tx.nonce = account.nonce + 1.
  • Replay resistance: Once accepted, the sender's nonce increments, so the same signed transaction cannot be accepted again.
  • Signature check: Only the account owner can authorize spending from that account.
  • Balance check: Sender balance must cover at least value + fee.
Important: If two conflicting transactions are broadcast from the same account, only the one with the currently valid nonce can be applied first. After that, the nonce changes and conflicting replays become invalid.

UTXO vs Account Model (Quick Comparison)

Compared with UTXO systems, account-model systems represent state more like a balance sheet. This can feel simpler for users and is the model used by Ethereum.
