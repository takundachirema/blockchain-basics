UTXO Model

What Is the UTXO Model?

The UTXO model (Unspent Transaction Output model) represents money as a set of spendable outputs. A transaction consumes existing outputs as inputs and creates new outputs for future spending. Instead of maintaining one mutable balance entry per account, the ledger tracks a changing set of outputs that are currently unspent.

Definitions used in this page:
  • UTXO: An output from an earlier transaction that has not yet been spent.
  • Input: A reference to a previous UTXO that is being consumed now.
  • Output: A newly created coin assignment (value + locking condition/public key).
  • Outpoint: The pair (txid, output_index) used to uniquely identify a previous output.
  • Change output: An output that sends leftover value back to the sender.

Core Intuition

  • You do not spend "part of an account balance"; you spend one or more whole UTXOs.
  • If selected inputs are larger than the payment, you create a recipient output plus a change output back to yourself.
  • UTXOs form a transaction graph: outputs are created, later referenced, and then removed from the spendable set.
  • Ownership is tied to public keys and unlocking conditions, not legal names.

UTXO idea: A payment output can later become an input to another transaction.

How Spending Works in Practice

  1. Select inputs: Choose one or more UTXOs you can unlock with your key(s).
  2. Create outputs: Add recipient output(s) and, if needed, a change output.
  3. Sign: Sign the unsigned transaction data for each input according to its locking condition.
  4. Broadcast: Send to the network for validation.

The model enforces conservation: total output value cannot exceed total input value (fees aside). Once an input is used, that referenced UTXO is removed from the UTXO set and cannot be spent again.

Multiple outputs: One consumed UTXO can create several outputs, such as a recipient payment and a change output.

Outpoint reference: Inputs identify exactly which prior output they spend using (txid, idx).

Validation and Double-Spend Protection

A node validates a new transaction by checking that its referenced inputs are currently in the UTXO set, signatures are valid for the corresponding locking conditions, and values are consistent. If a transaction attempts to spend an already-spent output, it is rejected as a double spend.

Takeaway: In the UTXO model, global state for spendable money is exactly the current UTXO set. Transactions are state transitions that remove old UTXOs and create new ones.
